# 微信小程序构建、上传与包体

命令从移动端仓库根目录执行。工程预算和依赖归属以 `scripts/weixin-package-policy.json` 为准，上传成功、体验版、审核和发布分别确认。

部署含义及首次发布步骤见[微信小程序部署说明](微信小程序部署说明.md)。

首次在本机配置小程序：

```bash
# 仅首次创建；已有本地配置不要覆盖。
cp project.config.example.json src/project.config.json
# 在 src/project.config.json 中填写自己的 appid，然后构建。
npm run build:weixin
```

`src/project.config.json` 已加入 Git 忽略，由微信编译器复制为产物的 `project.config.json`，不回写源码 manifest。真实 AppID 不提交；`src/manifest.json` 中的 AppID 保持空值。未提供本地配置时，CI 仍可验证构建，但产物不能直接用于正式上传。

发布配置启用 `minified`、`minifyWXSS`、`minifyWXML`，并关闭 `uploadWithSourceMap`。已有本地 `src/project.config.json` 也需同步这些 `setting` 字段，否则会覆盖默认配置。主包大小以微信开发者工具上传检查为准，超过 2 MB 会被拒绝；源码构建成功不能替代上传检查。

## 开发时自动更新

自动更新依赖完整链路：**保存源码 → uni 监听编译 → 开发目录产物变化 → 微信开发者工具自动编译/热重载**。开发者工具不会直接把 `.uvue` 源码编译成小程序。

日常开发推荐使用后台入口，避免终端或聊天结束后监听退出、微信工具却仍展示旧产物：

```bash
npm run weixin:open    # 启动/复用后台监听，确认当前源码已同步后打开固定开发目录
npm run weixin:start   # 仅启动/复用监听并等待当前源码同步，不打开工具
npm run weixin:status  # 检查后台/编译状态、源码是否一致、最后同步时间和日志路径
npm run weixin:stop    # 停止本仓库后台监听
```

后台入口使用 `.env.local` 等现有环境配置，启动时生成间距、排版与底栏；日志在忽略目录 `artifacts/weixin-output/dev.log`。源码内容指纹覆盖 `src`、构建脚本、依赖清单、Vite 配置和环境文件，状态只记录哈希，不保存配置内容。不会根据单个产物的文件时间判断版本，因为未变化文件会保留原时间。只有本轮编译成功、监听存活、源码及配置一致，才报告最新并打开工具；失败保留旧产物且状态命令返回非零。

后台每两秒检查状态，监听异常退出自动重启（同一源码最多三次）；源码变化后漏掉增量事件会在约十秒后重新完整构建，构建超过五分钟也会尝试恢复。环境文件、构建脚本、依赖清单、路由、排版/间距配置或源码文件结构变化会重启编译并重新生成配置。持续编译错误需修复源码，不能靠重试绕过。切换命令行 `VITE_*` / `NODE_ENV` 时先 stop 再启动，避免复用不同环境的监听。

关闭终端不影响后台监听，但电脑重启后需再次执行 `weixin:open`；此入口不安装系统开机服务。前台 `dev:weixin` 和后台监听只能选一个，同目录已有前台监听时需先在原终端停止。后台命令固定写开发目录，不受外部 `UNI_OUTPUT_DIR` 指向发布目录影响；发布构建与上传仍走原命令。自动化状态确认到磁盘产物为止，微信模拟器刷新仍需在工具里实际确认。

`dev:weixin` 和 `build:weixin` 通过 `scripts/run-weixin.mjs` 启动编译器，在 `artifacts/weixin-output/` 下使用独立临时目录。`scripts/weixin-output.mjs` 等待 Rollup 写出及 uni 静态复制全部完成，校验主题、页面、底栏图标及 JSON 后，再同步到稳定目录：新增依赖先写入，`app.js` / `app.json` 最后切换，随后删除过期文件；文件使用原子替换，未变化文件不重写，开发者工具的 `project.private.config.json` 保留。编译失败不发布半成品，发布命令若没有完成本次同步就退出失败，不能用上次产物继续检查或上传。同一输出目录只允许一个编译进程；开发和发布目录可以分别使用。

每次编译的临时产物（含相邻的中间目录）在退出后清理，编译缓存按稳定输出目录复用，避免每次重启新增一套缓存。开发监听的模块贡献报告单独写入 `artifacts/weixin-size/dev/chunks.json`，不会删除或覆盖发布构建的包体报告。

这是为避免当前 DCloud 编译器在启动时先清空目标目录：主题和静态资源随后才复制，微信工具可能在空窗中缓存删除事件，反复报 `theme.json` / `uvue.wxss` 缺失，即使磁盘文件已经恢复。不要直接调用 `uni -p mp-weixin` / `uni build -p mp-weixin` 绕过入口；Vite 会拒绝未经隔离的微信构建。开发者工具只打开下面的稳定目录，不导入内部临时目录。

| 使用场景 | 命令 | 开发者工具打开的目录 | 更新方式 |
| --- | --- | --- | --- |
| 日常开发 | `npm run weixin:open` | `dist/dev/mp-weixin` | 后台监听并自动恢复，打开前确认当前源码 |
| 前台诊断 | `npm run dev:weixin` | `dist/dev/mp-weixin` | 进程运行期间持续监听，关闭终端后停止 |
| 发布、正式包体检查 | `npm run build:weixin` | `dist/build/mp-weixin` | 每次手动重新构建 |
| 模拟数据验收 | 对应专项测试脚本 | `artifacts/` 下的测试副本 | 由测试脚本生成，不跟随业务源码自动更新 |

1. 从移动端仓库根目录运行 `npm run weixin:open`。使用前台诊断命令时，等待 `Build complete. Watching for changes...` 后再打开开发项目。
2. 在开发者工具中确认项目路径为 `dist/dev/mp-weixin`，开启文件修改后的自动编译/热重载。当前工具的控制台会显示「已开启代码文件保存后自动热重载」。
3. 保存源码后，终端应出现 `Incremental Compiling...`，随后再次显示成功监听提示；再确认模拟器已刷新且没有编译错误。仅看到进程存在或首次构建成功不算增量更新通过。

开发模式未配置接口时默认连接本机后端；需要沿用线上接口时，在 `.env.local` 设置 `VITE_API_BASE_URL=https://aiolife.top/api`。切换项目目录可能使用独立的登录缓存，需要重新登录。同一开发目录只运行一个监听进程；前台命令随终端结束停止，后台入口独立运行但不跨电脑重启。

普通页面、样式和逻辑修改可直接保存。以下为前台 `dev:weixin` 的额外操作；后台入口会自动处理配置与文件结构变化，手绘 SVG 转 PNG 仍需手动执行：

| 修改内容 | 操作 |
| --- | --- |
| 手绘图标 SVG | `node scripts/generate-tab-icons.mjs`，生成 PNG 后交给监听同步 |
| `spacing.json` / `typography.json` | 分别运行 `npm run spacing:generate` / `npm run typography:generate` |
| `pages.json` 底栏菜单 | `npm run tabbar:generate`；路由或分包结构变化后重启监听 |
| npm 依赖、分包策略、构建插件、环境变量 | 完成对应安装或配置后，停止并重新启动监听 |
| 删除或移动模块、调整模块归属 | 重启监听做一次完整开发构建，避免增量产物残留影响依赖判断 |

自动更新失效时按下面顺序排查，不要一开始就清除全部缓存：

| 现象 | 检查与处理 |
| --- | --- |
| 不确定当前是不是最新 | 先运行 `npm run weixin:status`；后台未运行时执行 `npm run weixin:open`，编译失败时查看 `artifacts/weixin-output/dev.log` |
| 保存后终端没有增量编译日志 | 确认监听进程仍运行、保存的是本仓库源码；退出后重新运行开发命令 |
| 终端报 `ENOENT`、虚拟模块缺失或插件错误 | 先修复构建错误；开发者工具清缓存不能修复源码或构建插件 |
| 终端成功，但模拟器内容不变 | 核对项目路径和自动编译/热重载设置；排除误开发布目录或模拟数据副本 |
| 提示找不到 `app.json` / `theme.json` / `uvue.wxss` | 确认使用上述命令、路径为稳定目录，并检查本次 `[weixin-output] 已同步` 成功提示；文件不存在时修复构建，不能创建空文件绕过。若文件存在且是旧构建留下的索引异常，执行下面的一次性恢复 |

开发者工具文件索引或编译缓存异常时，仅清理**文件缓存、编译缓存**，关闭当前项目，再在构建成功后重新打开。macOS 可用官方 CLI：

```bash
/Applications/wechatwebdevtools.app/Contents/MacOS/cli reset-fileutils --project "$PWD/dist/dev/mp-weixin"
/Applications/wechatwebdevtools.app/Contents/MacOS/cli cache --clean file --project "$PWD/dist/dev/mp-weixin"
/Applications/wechatwebdevtools.app/Contents/MacOS/cli cache --clean compile --project "$PWD/dist/dev/mp-weixin"
```

不要为此清理数据缓存、授权信息或登录状态。旧索引恢复后，正常重启上述编译命令会保留稳定目录，无需每次关项目或清缓存；首次构建仍需等完整同步成功后再导入。

**构建维护与验证边界：**分包插件的虚拟 ID 映射必须跨增量构建保留，因为 Rollup 会复用已解析模块；不能在每轮 `buildStart` 清空映射。uni 的增量输出可能不包含未变化的 `app.json`，依赖检查须合并已写出产物，而不是跳过检查。`tests/weixin-watch.test.mjs` 覆盖缓存 ID 重用、读取修改后的源码、不含 `app.json` 的增量输出，以及跨分包依赖仍被拒绝；这些测试不覆盖微信开发者工具自身的文件索引和缓存行为。

相关故障修复后，除了针对性测试，还应实际保存不同源码文件验证连续增量编译及模拟器刷新。工具或 DCloud 版本升级后需要重新确认兼容性。发布前另行运行正式构建和官方包体检查，开发产物不能作为发布包体通过证据。

`tests/weixin-output.test.mjs` 另覆盖完整性检查失败保留旧产物、未变化主题不重写、旧文件清理、私有设置保留、失败恢复、独立静态资源监听及重复启动阻断。排查重启问题时，应连续监测稳定目录关键文件是否存在，并实际检查模拟器；仅看最终磁盘文件存在不能证明构建过程中没有缺失空窗。

## 一条命令构建并上传

先登录微信开发者工具，在「设置 → 安全设置」开启服务端口，并配置上述本地 AppID，然后在本仓库执行：

```bash
npm run upload:weixin                           # 版本固定 0.9.0，说明默认「功能更新」
npm run upload:weixin -- --desc "修复首页交互"    # 自定义更新说明，也支持 -d
npm run upload:weixin -- --help                  # 查看用法，不构建、不上传
```

命令依次执行微信构建、现有 `postbuild:weixin` 官方包体检查、开发者工具 CLI 上传；任何一步失败即停止。每次上传都会重新构建，不复用旧产物。macOS 自动查找 `/Applications` 或用户 `Applications` 下的 `wechatwebdevtools.app`；其他安装位置通过环境变量 `WECHAT_DEVTOOLS_CLI` 指定 CLI 可执行文件的完整路径。编译时的 API 环境变量与 `build:weixin` 一致。

上传完成后在公众平台确认版本及体验版状态；此命令不提交审核或正式发布。

## 本地包体检查与 CI

```bash
npm run check:weixin-size       # 重新构建微信目标并检查包体
npm run build:weixin            # 同样自动执行 postbuild:weixin 包体检查
npm run check:weixin-size:only  # 只检查已有 dist/build/mp-weixin，适合诊断；不会重建源码
```

检查使用固定版本 `miniprogram-ci@2.1.31` 的 `getCompiledResult`，读取产物的发布压缩设置，再按编译后的 `app.json` 分包根目录统计 UTF-8 / 二进制文件字节数。主包及每个分包独立按 **1900 KB 预警、2048 KB 硬上限** 检查，主包额外执行 **1800 KB 工程预算**（1 KB = 1024 字节）；超工程预算、超硬上限、缺失产物、编译失败或发布配置漂移均返回非零退出码。预览的 `bigPackageSizeSupport` 不会放宽本地阈值。

微信构建还检查主包 JS 是否被主包页面、原生注册组件或 `app.js` 使用（包含间接依赖和 JSON 组件声明），发现仅分包使用或完全未使用的 JS 即失败。业务专属源码放入对应 `src/pages/<业务>/services/`；多个分包共用且不持有模块级共享状态的工具，可经审查登记在 `scripts/weixin-package-policy.json` 的 `scopedSharedServices`。构建插件为每个调用分包生成虚拟副本，源码仍只维护一份，嵌套工具保留相同分包归属；登录状态、缓存等单例继续引用主包，不能加入副本清单。H5 与 App 不启用此机制。主包组件自身的归属优化不由此项检查覆盖，微信开发者工具的最终质量检查仍需单独确认。

终端列出各包大小、剩余额度、主包最大的 10 个文件；`artifacts/weixin-size/report.json` 保留各包全部文件清单，`report.txt` 为简短报告，`chunks.json` 记录各 JS 文件的模块贡献和实际同步依赖（uni/Rollup 阶段字节数仅用于定位，最终限额以官方编译后的 `report.json` 为准）。微信构建开始即清除旧报告；若前面的 uni 构建失败，不会留下旧的体积通过报告。CI 的构建任务运行同一命令，并保存报告 7 天，超预算或超限会使任务失败。

检查在临时副本上运行，不改开发者工具项目，也不调用 `preview` / `upload`、不更新体验版。离线适配使用编译器默认项目属性和 `touristappid`，无需真实 AppID、上传私钥、IP 白名单或 CI Secrets；内部非密钥占位值只满足官方 Project 构造器参数要求，不用于鉴权。涉及插件或账号特定能力时不能据此声称已验证，当前检查会拒绝插件项目。此适配固定编译器版本，升级时必须重新验证；它统计编译后的文件字节数，不是 ZIP 大小，也未包含服务端最终封装开销，上传端仍保留最终校验。[微信官方编译接口](https://github.com/wechat-miniprogram/miniprogram-ci-dist#获取本地编译后的代码包)

编译进程的工作目录、临时项目和编译缓存统一放在独立的系统临时目录中，由外层检查进程在成功、失败或超时后清理，避免官方编译器的 MD5 缓存目录残留在仓库根目录。

工具会忽略开发者工具的私有运行配置，但若其覆盖了发布编译选项则直接报错，避免两套压缩配置产生误判。Node 25 的 Web Storage 与官方编译器存在兼容问题，检查进程及其子进程会单独关闭该实验特性；CI 继续使用 Node 22。

业务专属模块随分包存放：CBTI 海报组件及二维码在 `pages/personality`，聊天流与 Markdown 在 `pages/messages`，图谱布局在 `pages/relationship`，MCP 参数校验在 `pages/mcp`。公共目录中的源码默认可能进入主包；只有明确登记在 `scopedSharedServices` 且满足无共享状态约束的工具才由插件按调用分包生成副本，不能仅因调用方是分包就假定它会自动迁移。

重量 npm 依赖采用微信专用分包构建：`scripts/weixin-package-policy.json` 声明所属分包与导出，Vite 插件从锁定的原依赖生成分包私有副本。财务分包持有 Excel、ZIP、编码表；阅读分包持有 Excel；密码库分包持有 SM4 与 PBKDF2。主包需要的共享小工具仍在主包；已登记的无状态工具按上文机制归属调用分包。插件会拒绝重量依赖进入主包和普通分包之间的同步引用，Web/App 保持正常依赖解析。允许必要的分包间代码副本以换取主包余量；不删减 CSV、GBK、ZIP、Excel 导入或现有加密能力。维护步骤见 `AGENTS.md` 的“避免主包再次超限”。

## 微信登录与订阅通知

后端先执行用户表迁移，再由管理员在「系统配置 → 微信小程序与订阅通知」填写 AppID、AppSecret 并启用微信登录，保存立即生效。首次保存后台配置前仍兼容原微信环境变量。AppID 应与本地 `src/project.config.json` 的 `appid` 一致。AppSecret 不得放入客户端或 `VITE_*` 变量。能力未启用时自动保留账号密码登录。

首次微信登录可明确选择无需手机号的注册，或验证原账号密码后绑定。已有微信绑定后直接登录；当前客户端不调用旧手机号授权入口。临时票据只保存在页面内存，不能作为 Token 使用；取消授权可重试，凭证失效需要重新微信登录。新用户可在登录后设置密码，也可跳过。

旧手机号入口仍依赖微信主体认证与可用额度，不能将这些条件写成当前无手机号注册的前提。当前流程仍需配置隐私指引与合法域名。`tests/wechat-ui/run.mjs` 将源码复制到忽略目录，模拟平台回调验证交互与 390 / 768 / 1440px 深浅色，**不等同于微信开发者工具或真机验证**。不会给生产页面添加模拟入口。

在微信开发者工具中导入 `dist/build/mp-weixin`，配置自己的小程序 AppID。正式使用时配置 HTTPS request 合法域名；本地联调可仅在开发者工具中临时关闭域名校验。框架编译通过不等同于真机验证或审核通过。

微信小程序一次性订阅通知目前试点支持力扣未打卡提醒，在「我 → 通知设置」订阅并发送测试。测试会消耗一次订阅机会，渠道默认关闭；管理员可在系统配置表单填写模板和字段，AppSecret 加密保存且不回显。配置与验收步骤见 [微信小程序订阅消息接入](../../docs/微信小程序订阅消息接入.md)。Web、H5 和 App 不调起小程序订阅授权。
