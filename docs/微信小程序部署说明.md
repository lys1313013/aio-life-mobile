# AIO Life Mobile 微信小程序部署说明

“部署到微信小程序”是把 mobile 项目的代码编译成微信能运行的程序，上传到微信平台，再按需要设置体验版或审核发布，让用户在微信里使用 AIO Life。

本项目使用 uni-app x + Vapor，已有微信构建入口。整体流程是：**配置 → 编译 → 上传 → 体验版验证 → 提交审核 → 正式发布**。上传、审核、发布是不同阶段。[DCloud 发布说明](https://zh.uniapp.dcloud.io/quickstart-hx.html)

## 部署后代码在哪里运行

| 部分 | 位置与作用 |
| --- | --- |
| mobile 小程序 | 编译产物上传到微信，用户打开后在手机微信中运行界面和交互 |
| Spring Boot 后端 | 单独部署在服务器上，提供登录、查询、保存等 API |
| 数据库与文件存储 | 由后端管理，保存生活记录、账号数据和文件 |

调用关系：**手机微信里的小程序 → HTTPS API → 后端 → 数据库或文件存储**。小程序上传完成后，仍然需要可访问的后端服务。

## 首次发布前准备

- 微信小程序账号、对应的 AppID，以及开发者工具上传权限。
- 微信开发者工具、Node.js 20.19+ 和 npm；本项目开发使用 Node 22。
- 可公网访问的 HTTPS 后端，例如项目历史上传使用的 `https://aiolife.top/api`。
- 在微信公众平台配置服务器合法域名：API 对应 request 域名；上传、下载及第三方调用按实际使用补充对应域名。以当前后台要求为准，正式使用不能依赖开发者工具关闭域名校验。

API 地址包含 `/api`，合法域名填写对应的域名地址，例如 `https://aiolife.top`。

## 实际操作步骤

### 1 配置本地 AppID

在 `aio-life-mobile` 目录执行：

```bash
npm ci
# 仅首次创建，已有配置不要覆盖。
cp project.config.example.json src/project.config.json
```

打开 `src/project.config.json`，填写自己的 `appid`。此文件已被 Git 忽略；真实 AppID 只保存在这里，`src/manifest.json` 与示例文件中的 AppID 保持空值。

发布设置保持 `minified`、`minifyWXSS`、`minifyWXML` 为 `true`，`uploadWithSourceMap` 为 `false`。

### 2 编译发布包

```bash
VITE_API_BASE_URL=https://aiolife.top/api npm run build:weixin
```

生产构建未配置 `VITE_API_BASE_URL` 时默认使用 `https://aiolife.top/api`，直接执行 `npm run build:weixin` 也使用此地址。部署到其他环境时，将命令中的地址替换成目标 HTTPS API；检查本地 `.env*` 文件，避免开发地址覆盖生产默认值。该变量在编译时进入客户端包；修改地址后需要重新编译、上传。不能使用手机无法访问的电脑 `localhost`，也不能在 `VITE_*` 中放密码或 AppSecret。

产物位于 `dist/build/mp-weixin`。命令会自动检查包体，本项目主包预算为 1800 KB（以 `scripts/weixin-package-policy.json` 为准），每包硬上限为 2048 KB，最终以微信实际上传校验为准。构建失败时先修复，不继续上传。

### 3 导入并上传

日常上传可以直接执行一条命令，自动重新构建并完成包体检查后上传：

```bash
npm run upload:weixin                        # 版本固定 0.9.0，默认说明「功能更新」
npm run upload:weixin -- --desc "更新首页交互" # 覆盖本次更新说明，也支持 -d
pnpm run upload:weixin                       # 同样支持 pnpm
pnpm run upload:weixin --desc "更新首页交互"   # pnpm 直接传入脚本参数，不加额外的 --
```

首次使用先登录微信开发者工具，并在「设置 → 安全设置」开启服务端口。macOS 自动查找默认安装路径；自定义安装位置可用 `WECHAT_DEVTOOLS_CLI` 指定 CLI 完整路径。命令沿用 `build:weixin` 的 API 环境配置；构建、包体检查或上传失败都会停止。上传成功后仍需在公众平台确认版本和体验版状态。

脚本先通过 `cli open` 打开发布项目，再执行上传，让上传使用已打开的项目进程。当前开发者工具的 CLI 隐藏后台初始化失败后可能缓存失败的 Promise，后续重试持续报同一 TLS 错误；显式打开项目可以绕过这一路径，无需关闭代理或修改网络配置。

上传脚本使用微信 CLI 的 `--info-output` 获取本次服务端成功回执，每次使用独立临时目录并在结束后清理。部分 CLI 错误会打印 `[error]` 却以退出码 0 结束，因此仅退出码为 0、IDE 已启动或 AppID 已识别均不能证明上传成功；缺少回执或回执无效时脚本会报错退出。如果打开项目后仍有 TLS 断连，应按当次网络错误排查，不通过关闭证书校验规避，也不自动重复上传结果不明的版本。

也可以保留开发者工具界面操作：

1. 在微信开发者工具中导入 **`dist/build/mp-weixin`**，使用与本地配置一致的 AppID。
2. 检查页面、接口地址、域名和包体，使用手机预览验证登录与主要功能。
3. 点击“上传”，填写版本号 `0.9.0` 和说明，例如 `功能更新`。
4. 看到明确的上传成功结果后，在微信公众平台的版本管理中确认对应版本。

`npm run build:weixin` 负责生成并检查产物，不会自动上传、更新体验版或发布。

### 4 隐私与账号配置

先按[隐私政策与账号注销](../../aio-life-server/docs/隐私政策与账号注销.md)同步后端当前结构和接口，在系统配置填写 `privacy.operator`、`privacy.contact-email`，并在微信公众平台补齐真实的用户隐私保护指引。注册时的自建协议确认不替代微信平台的接口授权；在真机验证头像、文件、剪贴板等相关能力及拒绝行为。

### 5 体验和正式发布

在微信公众平台将上传版本设为体验版，添加体验成员，用手机扫码验证。如果只供自己或指定成员测试，可以停在体验版阶段。面向普通用户上线时，完成平台要求的信息、类目、隐私指引等配置，再提交审核；审核通过后执行发布。

| 阶段 | 表示什么 |
| --- | --- |
| 编译成功 | 本地生成了小程序代码 |
| 上传成功 | 微信平台收到了一个开发版本 |
| 体验版 | 被授权的体验成员可以扫码使用 |
| 审核通过 | 微信审核通过，尚需执行发布 |
| 正式发布 | 该版本正式供用户使用 |

## 本项目的补充说明

微信身份登录需要先完成后端迁移与部署，再由管理员在「系统配置 → 微信小程序与订阅通知」填写 AppID、AppSecret 并启用微信登录，保存后立即生效。部署侧配置稳定的 `AIO_LIFE_NOTIFICATION_ENCRYPTION_KEY`；仅在首次保存后台配置前兼容原 `AIO_LIFE_WECHAT_MINI_*` 环境变量。当前客户端支持无需手机号的微信注册，旧手机号接口仅用于兼容。两端 AppID 必须一致，AppSecret 只保留在服务端；未启用时客户端保留账号密码登录。详细步骤见[后端微信登录说明](../../aio-life-server/docs/微信小程序登录.md)。

后续只修改客户端时，重新编译、上传并走对应发布流程；修改接口或数据库时，还需要部署后端及必要迁移。提交前验证遵循仓库 README 与 AGENTS.md。

微信在 `pages.json` 开启 `custom: true`，保留四个 tab 页面及 `switchTab` 缓存语义。`src/custom-tab-bar/` 仅为空适配器，不绘制底栏；可见底栏由 `TabPage.uvue` 的 flex 布局统一承载，`PageTabBar.uvue` 与页面在同一渲染层，安全区仅预留一次。弹窗通过 `root-portal` 使用一张全屏遮罩覆盖内容和底栏，不同步第二张遮罩，也不隐藏底栏或补像素接缝。弹窗与时间选择器只避让系统安全区／键盘，不再扣除底栏高度；固定悬浮按钮仍避让底栏。`prebuild:weixin` 从 `pages.json` 生成 `src/services/tab-bar.generated.json`，菜单变更后可运行 `npm run tabbar:generate`，`npm run tabbar:check` 校验，禁止手改生成物。主题、间距和排版直接复用客户端公共配置。H5 / App 保留原有底栏。
